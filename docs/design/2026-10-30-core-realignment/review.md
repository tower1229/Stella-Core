## 关键修订一：把“四类资产分权”补成不重叠的当前语义归属规则

**风险所在：**草案 §1 的明确偏好、普通事实/决定、带来源的长期理解在实际语义上会重叠。比如“不要把我的暂时回应解释成全局偏好”，既能成为 USER 指令，也能成为工作说明的关键解释；“本期先架构后纵切片”也可能同时出现于 MEMORY 决定与 Core 工作说明。不同文件各有 writer，仍可能形成两个“当前有效解释”。单资产原子发布并不能自行解决这种跨域歧义。

**最小修订：**在 ARCH-04 增加一页归属规则与两个冲突样例，而不是新增全局画像库或统一事务平台：

1. 每份首片工作说明明确其主题/适用范围、权威资产身份、当前版本与失效关系；宿主中的同题内容仅作为历史证据或指向该资产的非权威线索。引用版本和原稿副本都不成为第二 writer。
2. 与既有 USER/MEMORY 内容冲突时，不以“Core较新”或模型自行分类静默跨域覆盖；显式返回冲突及候选归属。首片仍只改工作说明，不顺带改 USER、不自动把局部解释晋升为人格结论。
3. 声明最小保证是“受控入口返回该主题当前权威”，不是“宿主所有历史和模型所有回答已硬性消除旧解释”。对后者保留跨会话/压缩/恢复的行为验收目标，不以首片不覆盖为由删去，也不冒称已满足。

**出口证据：**同一条纠正落在两类信息交界时，能指出唯一当前归属、另外一处是什么、冲突如何暴露；不需要跨 USER/MEMORY/Core 的大事务。若靠新增索引、统一总线或第二套会话库才能说明归属，应先缩小首片主题。

## 关键修订二：隔离研究覆盖“工具输出之后”，不能只证明入口有权限

**风险所在：**草案正确禁止受保护内容走普通 supplement，也承认工具 ctx 不等于来源授权。但“显式授权工具供给”之后，正文与解释可能进入宿主历史、raw transcript 索引、flush、dreaming 或后续上下文。入口允许本轮读取，不自动等于允许长期保留、自动学习或向其他受众再次供给。仅写“停用对应自动路径”还没有证明这些路径实际可按所需粒度停用。此处若未解决，既可能泄露用途，也可能让已取代解释从原生记忆复活。

**最小修订：**ARCH-02/03 对首片的一份合成工具结果作一张有限流向表：工具返回 → 对话记录/压缩 → 可检索记忆/自动整理 → 后续消费；逐项列已有官方控制、实际适用范围、未知与默认行为。身份/受众、来源读取许可、处理许可、持久保留/学习许可分别记录，不能互相推导。

- 先以静态可达路径研究，复用 [前期静态研究交接](../../../.task-control/reports/CORE-RES-001/handoff-20261030.md) 的 supplement、admission 与直接写边界；不穷举全 SDK。
- 若现有宿主不能局部隔离某个副作用，先限定首片仅使用合成资料或明确获准该处理范围的域，报告受保护真实资料路径仍不可用；不能声称只“关闭该路径”就已安全，也不能擅自全局改用户配置。
- 研究应给出关闭或限定的可行性证据，而非执行关闭。现有使用权限不被评审重新解释，亦不因材料在本机/沧海 Git 中而扩张。

**出口证据：**至少覆盖“当轮可读但不可自动学习”和“已取代说明仍在旧 transcript”两例。若未找到可信边界，阻塞相应真实资料流程，不阻塞合成契约研究，更不据此另造宿主。

## 关键修订三：把实现门槛改为实际安装版本上的可观察小契约，删除隐含接口承诺

**风险所在：**草案总体谨慎，但“已核公共 plugin LLM 接缝”、真实当前作者原话来源、工作说明发布与未来回答接续仍是不同层面的条件。公开字段存在不证明在当前 harness 中被填充；静态10.8研究不证明现有机器的运行契约；Host Agent 能产出结构化文本不证明其文本就是已认证作者澄清。固定模型名和 `low` 也不能在此评审中当作已验证可用的调用配置。

**最小修订：**ARCH-02/05 的交付明确分成以下三层，优先 Host 内既有判断路径，不为独立 LLM 接缝另造推理服务：

1. **安装事实：**只读确认既有安装版本、实际 harness、启用插件与公开 exports/回调路径。10.8 是研究参照，不要求降级或另搭环境。
2. **技术契约：**在获准范围内后续用合成固定结构响应验证实际公开入口中的身份/受众/活性字段、明确澄清的可信来源、来源版本、CAS/幂等发布和下一请求读取。缺字段应真实拒绝，不能由模型参数、sessionKey 或旧对象身份补造。单资产恢复验证采用可读自含资产与历史引用，不要求复制整个 Host 数据库。
3. **语义效果：**明确哪些案例仍待真实模型和作者判断。后续自然请求是否使用新理解、压缩/新会话/恢复是否接续，是行为证据，不等于文件回读成功。模型/服务可用性、参数、材料和费用应在调用前另核；当前只保留目标配置，不产生真实调用授权。

**出口证据：**一张“已静态确认／当前环境已观察／尚未知”的小表，加一条最短合成路径的验收定义。没有可信当前作者来源时，可完成受控读取与候选提案，但不得把候选当作者确认自动发布；不得将降级/缺数据包装成完整流程成功。

## 可以并行的研究边界

| 研究 | 独立交付与停止条件 | 明确不做 |
|---|---|---|
| 公开接缝与现有环境（ARCH-02） | 列实际环境可用的最少字段、可信来源与缺口；判断合成读取/提案/发布入口哪些可接，证据到此停止 | 不先修旧 unknown method，不启动旧 runner，不换身份/权限，不新搭非必要环境 |
| 单片输出流向与原生 writer（ARCH-03） | 对一类工作说明和一条工具结果确定目标、保留/学习范围、现有可控边界；未知如实标注 | 不审计全部 SDK、不改配置、不搬 USER、不做全库迁移或后台平台 |
| 单资产契约与语义样例（ARCH-04） | 一份工作说明格式、两例权威交界冲突、一次纠正/重试/旧候选/恢复的预期结果；仅必要发布记录 | 不保留旧 schema 为约束，不实现新数据库/全局事务，不调用真实模型 |

三路可以在方向评审期间并行只读研究，互相不以旧代码全绿为依赖；进入 ARCH-05 时只汇合**本片**真正需要的接缝、隔离和资产契约。某自动路径未证实，不自动阻断其余合成研究；但不能在首片依赖它时绕过门槛。项目写入仍由协调者指定的唯一写者处理，本报告不分派或恢复执行任务。

## 采纳建议

保留恢复稿的增量接入、首片单资产、USER不联动、模型判断与确定性发布分开、技术与真实语义验证分开。增加上述三处窄修订即可，不需要改写成新平台。对“更懂用户且持久有效”的目标保留分阶段证据，不把一个工作说明技术闭环冒充完整人格/长期记忆验收。
