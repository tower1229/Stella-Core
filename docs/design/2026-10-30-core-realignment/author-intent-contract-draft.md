# ARCH-04：单份作者意图工作说明最小契约

日期：2026-10-30。状态：**设计草案，待经理审定及技术证据；不是实现、运行验收或实施授权。**

## 结论与范围

首片只做一件事：围绕一个明确主题，把作者原意、解释和未决分开，允许一次有可信来源的纠正替代本资产内旧解释，并在后续受控读取时指出当前版本。必要发布单位仅为**这一份资产的当前内容、来源绑定和修订/幂等记录**。不写 USER，不自动同步 MEMORY，不新建数据库、通用事件总线、全局权威注册表或跨宿主文件事务。

本稿依据同目录 `proposal-reviewed-draft.md` 与 `work-packages-reviewed-draft.md`。它们来自线程恢复的源稿再修订，原临时文件丢失的溯源状态不变。本轮仅读取这两份设计文档并写本稿，没有读取 Mac、项目代码、私人资料或真实 Host 状态，没有运行代码、测试或模型。以下人物、资料、事件及版本标签全部为**合成样例**；版本名不是实际 Git commit/hash，样例中的授权条件也不是真实授权凭证。

## 1. 最少逻辑信息：允许一份可读文件承载

以下是必需含义，不是数据库 schema、既定 API 或固定序列化格式。可选择一个有明确章节的 Markdown 资产；具体可机械校验的编码由后续实现确定，不强接旧 Understanding/Work schema。

| 信息 | 最小含义与限制 |
|---|---|
| 资产身份与范围 | 稳定资产 ID、主题、适用任务/阶段、明确不适用范围；说明本资产是该范围作者意图解释的唯一发布位置，不自称所有相关事实或用户人格的权威 |
| 当前版本 | 不可混淆的版本身份；当前发布指向的完整资产内容。不得仅凭墙钟时间选新旧 |
| 原意 | 忠实的原意概括，逐项指向作者证据；原稿保持原样。概括不伪装成逐字引语，解释不伪装成作者自述 |
| 来源 | 来源 ID、原始角色/作者、版本身份、定位点、用途（支持/反证/澄清），以及最小可复核片段或可自含恢复的原件引用；转述、模型推断与作者表达显式区分。来源身份不是访问许可 |
| 已定 | 作者已明确的前提/约束及证据，不把助手建议和一次情境反应放入全局偏好 |
| 候选 | 尚未被作者确定的解释/方案，注明提出者、依据与适用范围；不具有当前指令地位 |
| 未决 | 尚缺什么、为何影响判断、需要什么澄清；空列表必须表示本范围已检查无已知未决，不表示全世界无未知 |
| 当前解释 | 对本次任务应怎样理解的有限结论、证据及边界；存在归属冲突时标为“该项未决”，不能仍输出一条无条件当前结论 |
| 修订关系 | 本次修订 ID、前版、替代/限定/新增的本资产内项、理由及触发来源；被取代解释仍可历史查询，不再作为当前值返回 |
| 已知权威交界 | 仅列本片实际遇到的 USER/MEMORY 引用及版本、冲突点和状态。不是另建它们的影子画像；未遇到不等于证明不存在冲突 |
| 发布凭据 | 稳定操作 ID、该操作的内容身份、结果版本；与本次修订共同持久化，用于响应丢失后的重试辨认，不使用 toolCallId 自动代替业务操作 ID |

资产内不保存可重放授权、访问令牌或永久 grant。每次读取、发布和恢复后的消费都须在入口获得当前资格；允许读取不等于允许保留、学习或再次投递。相关 Host 能力由 ARCH-02/03 证明，本稿不能补造。

## 2. 读取与发布：最小行为契约

### 2.1 受控读取

- 请求“当前”时，返回完整当前版本、范围、当前解释及已知未决/冲突；不从旧缓存或旧 transcript 选择一段假装当前。
- 请求“历史”时，返回指定版本并明确历史地位。旧原意证据可以仍有效，但已被取代的解释不能因此复活。
- 无权限、缺可信调用上下文、来源无法读取、检索未完成、资产不存在、版本不可确认分别报告；不能统一伪装成正常无结果。未经授权不返回正文、标题或敏感引用。
- 后续自然请求须重新取得当前资格与版本。此契约仅管受控入口；模型是否实际正确使用返回内容，另属语义验收。

### 2.2 发布意图必须携带什么

最少包含：目标资产 ID、**预期资产版本**（首次创建需显式预期不存在）、稳定操作 ID、待发布内容身份、已读来源的预期版本、触发本次修订的可信作者来源、修订范围及关系。内容身份应能区分同 ID 不同提案；具体哈希/编码并未在本设计中实现。

发布前验证：当前请求及用途资格成立；引用可定位且版本符合预期；作者澄清不是模型自报；本资产预期版本仍匹配；已知交界冲突未被掩盖；候选和未决没有被误写为已定。真实作者身份/来源的公开接缝尚待 ARCH-02，不以模型参数、session 标签或本稿文字替代。

### 2.3 一个小提交边界

当前内容、来源绑定、本次修订关系及操作结果身份必须一起生效：成功后可读一个完整新版，失败则仍为完整前版或明确不可用，不能出现新版正文配旧取代关系。复用符合契约的既有 Git/原子发布/CAS 能力优先；具体实现尚待核实，**Git 存在本身不证明并发 CAS 或崩溃一致性**。

宿主索引、缓存和投影不在提交单位中；它们滞后时不得声称全部同步。源稿只读，USER/MEMORY 不在事务内。外部来源已发生版本变化时拒绝本次旧来源发布，重新读取并形成新提案；不能仅更新版本号重放旧理解。相同来源的新副本不能增加独立证据数量。

### 2.4 重试、冲突与不确定结果

- 同操作 ID、同内容身份且此前已成功：在重新验证当前请求资格后返回原发布结果，不新增修订；同时区分“该操作曾发布 v2”和“现在当前是 v3”。不得把历史成功结果说成当前值。
- 同操作 ID、不同内容身份：拒绝为操作身份冲突，不覆盖原结果。
- 未曾成功而预期版本已过期：版本冲突，不能靠自动重试覆盖新解释。重读后如需再提案，保留与原提案关系，但使用新的操作身份。
- 提交结果不明（例如响应丢失）：报告结果待确认，查本资产持久发布凭据；未查清不另建重复资产、不宣告成功或失败。无法核验时保持不可确认，不靠内存成功标志推断。
- 首片幂等历史随资产保留，不先设计裁剪平台。若未来裁剪，必须单独定义重试窗口；本稿不声称无限期无存储成本。

## 3. 一份完整的合成说明（纠正后的版本）

**资产：**`synthetic/harbor-exhibit-intent`；**当前版本：**`v2`；**范围：**虚构“港湾展览”本次内部说明稿的作者意图；不代表作者一般写作人格，不决定真实发布时间或任何外部行动。

**合成来源：**

- `S1@a`，作者原始简报，第1段：“做一份内部说明，先让团队看懂展览主题。”
- `S2@a`，助手旧解释：“内部说明越短越好，应省略论证附件。”这是助手解释，不是作者表达。
- `S3@a`，作者明确纠正：“正文可以短，但这次必须附论证过程；不是所有材料都要附。”
- `S4@a`，助手候选：“可把论证拆成三张表。”尚未获作者选择。

**原意：**为团队形成可理解、可讨论的内部主题说明（S1）；本次需要可检查的论证附件（S3）。

**已定：**内部用途；正文可短；本次附论证过程；不能外推为所有材料都要附论证。

**候选：**三张表的呈现方式（S4），尚未决定。

**未决：**附件长度与图表格式未定；它们不阻止确认“必须附论证”，但会影响下一步排版。

**当前解释：**正文负责简明介绍主题，附件保留本次论证；不能为了正文简短而删去附件。此解释仅用于本次说明稿。

**修订：**`R2` 由 `v1` 到 `v2`；依据 S3，以“正文与附件职责分开”替代本资产旧解释 `I1=省略论证附件`，当前解释为 `I2`；不改 S1/S2，不把 S4 晋升为已定。

**发布意图样例：**`operation=CORR-001`，`expected_asset=v1`，`expected_sources={S1:a,S2:a,S3:a,S4:a}`，内容身份记作 `payload-B`。这些只是测试符号，非实际 SDK 字段、凭证或哈希。

## 4. 两例权威交界冲突

### A. 局部写作要求 vs USER 一般偏好

**合成输入：**假想 USER 的 `U@u1` 写着“一般采用简短正文，不附长论证”；本资产原 v1 沿用省略附件。新的 S3 明确说“这次必须附论证过程；不是所有材料都要附”。

**预期：**这是有明示范围的局部例外，不是作者整体偏好改变。工作说明只发布本主题 I2，并注明 U@u1 是一般偏好、S3限定本次例外；不复制整份 USER、不更新 USER、不创建“作者现在偏爱长文”的第二画像。后续本主题读取必须显露局部范围，不能无说明地在两个来源间二选一。

**歧义负例：**如果澄清只有“别那么短”，不足以判定本次例外还是全局偏好变化，则该项留为候选/归属未决，不发布“全局改成长文”结论；可请求一个影响归属的澄清。当前资产可保留其他确定部分，但该项不能同时被标为已定当前指令。

**设计可验收点：**同一条有明确范围的纠正不要求作者再维护另一份画像；没有明确范围时不假装已解决。是否正确理解自然语言中的范围仍属语义效果，不是字符串规则。

### B. 作者意图说明 vs MEMORY 的任务决定

**合成输入：**假想 MEMORY 的 `M@m1` 记载“港湾展览周五对外发布”；作者新澄清 `S5@a` 为“我说周五是内部审阅，不是发布”。

**预期：**工作说明可在其范围内发布“作者所指周五是内部审阅”的解释及 S5 依据，同时显式列出与 M@m1 的已知冲突；不能宣称 MEMORY 已被纠正、不能替用户改发布日程或执行发布/取消。对于“是否周五对外发布”这一跨域行动决定，结果必须是**冲突未解决，不能据 M@m1 或本资产单方采取行动**。本资产只拥有作者意图解释，不自动夺取外部任务状态权威。

**后续边界：**若确需修订原生任务决定，另由已有获准原生路径处理并取得结果证据，首片不联动。确认不必要求作者重复解释已有明确原意；待补的是合法更新路径及其结果，不是重复索取同一句澄清。若该原生路径暂不可用，保留可用的作者意图解释与可见的行动阻塞，不能伪装全局同步完成。

**设计可验收点：**允许保存更准确的理解，但不把“理解已修订”冒充“所有业务状态一致”。冲突字段必须随受控当前读取一起返回，不能藏在审计历史中。

## 6. 经理可以验收什么、还缺什么

### 本设计的验收边界

可审查：字段含义足够区分原话/解释/候选/未决；两类权威交界不静默跨域覆盖；单资产发布包含必要修订与操作结果；纠正、重试、冲突、旧候选、恢复有明确预期；USER不联动且没有新平台需求。这是 **ARCH-04 设计可审**，不是 ARCH-05 技术通过。

### 进入薄纵切片仍缺的证据

1. **ARCH-02：**实际新版 Host/harness 能提供哪些可信请求者、受众、当前作者来源、活性及取消信息；当前来源资格如何取得。缺失时对应受保护读取/作者确认发布不可用，不能用样例字段补造。
2. **ARCH-03：**工具返回后的 transcript、压缩、索引与自动学习流向；局部隔离能否实施。无法证明时限合成/明确允许处理域，不擅改全局配置，也不声称已关闭未知路径。
3. **发布实现审查：**现有 Git/原子发布/CAS 代码是否满足本片单资产边界、来源检查、操作身份保存与崩溃恢复；本轮没有读取代码，不能认定可复用部分已成立。不得因此先修完整旧 runner。
4. **语义评阅：**合成样例可以定义期望，固定响应只能验证技术流程。作者范围判断、反证识别、同义旧解释不复活、压缩/新会话后的实际表现需要另行获准的真实模型与原意评价；模型/API、参数、材料和费用均未由本稿验证或授权。

设计研究到此停止，不扩展全库传播、主动学习、全量迁移或跨宿主事务。上述依赖未证实时报告具体缺口，可继续独立设计，但不把未知标为已通过。
