## 1. 两个维度，分别定责

**接入拓扑：增量接入。** 保留memory-core、原生context/Agent Loop、会话、模型和工具执行。Stella作为普通插件，用公开适配及受控工具补认知与来源差异；不选择替换全部memory/context slot，也不要求Core声明memory kind。corpus/prompt supplement仅是可选附加接缝，不是本方案的私有资料入口或前置条件。

**语义权威：按信息性质分权。** 权威是“谁有权发布这项信息的当前版本”，不是“谁另建数据库”。Core发布的可迁移资产优先仍归沧海，索引、缓存和声明为投影的副本可重建。

| 信息 | 唯一权威及写入责任 | 其他位置的地位 |
| --- | --- | --- |
| 原稿、作者原话、聊天附件等原始资产 | 沧海保留原始内容、角色和来源；Host记录须先核实受支持且获准的导出/接入，再归档；当前不宣称该路径已验证 | 检索摘要不是原件，也不是新的独立证据；不复制含凭据的Host数据库进Git |
| 已获准进入宿主的明确偏好/协作指令 | 原生USER及官方编辑路径；用active/superseded表达当前指令 | Core引用它，不再保存同一份有效画像；一次情境反应不能自动升级为全局偏好 |
| 普通非画像事实、决定、日常记忆 | 原生MEMORY/每日笔记承担其声明范围 | 相关原始来源仍留存；不另在Core维护等价事实库 |
| 需来源、情境、反证、取代关系的理解及长期工作说明 | Core拥有语义发布权，资产可读且可迁移地留在沧海 | Host按需消费当前获准内容；不在USER/MEMORY再造同一份独立有效权威；正文仍由原稿拥有 |

### 权威交界与冲突规则（首片范围）

上述分类不是自动互斥的分区。首片工作说明必须声明主题/适用范围、唯一权威资产身份、当前版本与取代关系；宿主中同题内容只能是历史证据或指向它的非权威线索，不另发布同题当前解释。

- 局部解释与既有 USER 偏好重叠时，不能由模型自行把局部反应晋升为人格或全局指令；若当前意义冲突，返回冲突及候选归属，不静默以“Core较新”覆盖 USER。
- 工作说明与 MEMORY 的决定重叠时，同样先暴露归属冲突；首片只修订工作说明，不自动把它复制成 MEMORY 的第二份有效权威。两个冲突样例由 ARCH-04 明确预期结果。
- 最小系统保证是受控入口返回本主题当前权威，不是宿主全部历史和任意回答已消除旧解释。跨会话、压缩及恢复后的持续行为仍是验收目标，需独立证据，不能由单文件回读替代。

只补一页归属规则和必要样例，不建立全局画像库、跨全部 Host 文件的大事务或第二套会话系统。

USER的原生格式文件应作为单一资产纳入沧海完整副本/恢复路径；具体受支持的workspace布局与归档关系先验证，不默认搬生产目录、采用symlink或双向同步。运行时若存在复制品，须声明来源/版本和唯一写入方向；不能两个文件各改一套再互相学习。长期工作说明只保存续接所需语义，不复制全文，也不强保旧Understanding/Work schema。

“原生全承载、Core只交候选/差异规则”保留为简化对照。它适合全部信息已进入原生允许域、且可以接受理解取代/传播主要靠模型纪律的范围；当前不能据文件编辑或来源引用就认定其等价满足受保护来源与统一修订保证。若未来实证等价，再缩减Core资产范围，不以保留旧代码决定拓扑。

## 2. 最小Core：三个逻辑职责，无新增通用服务

| 职责 | 公开接缝与边界 |
| --- | --- |
| 来源与请求适配 | `api.registerTool`及v2工具上下文；消费Host提供的memoryAudience、requester及currency guards，再结合来源/处理/投递许可。factory没有runId；execute第一参数是toolCallId。公开hook可辅助关联，不能把关联标签变成授权，也不能从owner/admin/session推导来源权限。缺可信字段或当前原话来源时，相关受保护读取/学习不开放。 |
| 认知语义判断 | 优先在Host Agent任务中完成结构化判断；若确需独立结构输出，先核实当前安装版本上的公开plugin LLM接缝、参数及调用授权，未证实前不依赖它，不新增独立推理服务。LLM分清作者陈述、解释、候选、适用范围与未决；确定性代码负责结构/引用/权限/执行，不能用关键词规则代替理解。 |
| 可迁移语义发布 | 一个发布流程提交当前工作说明及本次修订关系，绑定已读来源和预期版本。重用现有原子发布/CAS/幂等能力中适合新契约的部分，不强接旧schema、旧能力编排或native lease。MemoryProviderHandle没有write，不将它当写入接口。 |

原生USER更新以静态研究中的`agents.files.get/set`作为复用候选，当前安装、调用身份及权限仍须核实；多用户`personal_instructions`只在真实requester及官方资格成立时使用。前者的文件hash冲突/队列、后者的请求者保护，都不是跨理解资产事务；也不意味着业务工具自动拥有操作员RPC权限。首个工作说明流程不同时改USER，避免制造两套写入的耦合前置。

可选`api.registerMemoryPromptSupplement`/`api.registerMemoryCorpusSupplement`只承载固定公开或已验证允许全体消费方使用的域，包括已经审查为可公开的线索；标题、路径和索引也可能敏感。它们缺完整caller authority/audience/purpose接缝，**受保护沧海内容不能经普通supplement直接注入**。受保护正文与理解只经显式授权工具供给；不调用private-local facade或恢复旧SQL桥。

### 工具返回之后的资料流向门槛

显式工具入口授权不自动授予 transcript 留存、raw indexing、压缩、flush、dreaming 或后续受众消费的权限。ARCH-02/03 必须为首片一条合成工具结果列出“返回 → 对话记录/压缩 → 检索/自动整理 → 后续消费”的有限流向表，逐段记录官方控制、适用粒度、证据及未知。请求者/受众、来源读取、处理、持久保留/学习许可分开，不能由本机文件可读或来源标签互相推导。

至少说明“当轮可读但不可自动学习”和“已取代解释仍在旧 transcript”两个负例。只声明关闭不足以证明实际可隔离：若没有可核实的局部控制，首片限合成资料或明确获准对应处理范围的域；受保护真实资料流程仍不可用，不擅自全局改配置。研究给出控制可行性证据，不执行关闭，不扩张现有权限。

## 3. 首个核心流程：恢复并修订一份作者意图工作说明

1. Host用已有获准USER和原生记忆取得一般协作背景/允许域线索；Stella受控工具读取当前获准原稿、作者表达及已有工作说明。未命中不能推断“作者从未表达”。
2. LLM恢复作者原意和证据，分开已定前提、助手候选与未决；关键不清楚时提出会改变判断的澄清，不擅自添加积极结尾或全球人格结论。
3. 有来源可信且可确认归属于作者的明确新澄清时，Core修订**同一份**工作说明，保留原意、依据、已定/候选、未决与当前解释及必要修订缘由。原始作者表达不被改写；被取代解释保留历史身份但不再由受控读取当当前有效状态。第一片不自动更新USER或向MEMORY写第二权威。若缺可信作者来源，可在既有许可内读取及形成候选，但不将模型提案当作者确认自动发布。
4. 当前回答消费这份已发布说明；下一自然用户请求重新取得当前来源资格与资产版本。Host历史可以保留为过去对话，不充当当前事实/许可。实际回答是否持续符合原意必须另做语义验证。

这一流程不规定旧run表、精确native readback、清理观测或旧runner为设计前置。首批只做一个可解释的作者意图资产，不展开全库传播、后台学习和所有业务领域。

## 4. 保证分层与必要事务

- **用户必需目标：**资料完整可迁移；理解有来源和情境；候选/未决不被抹平；一次明确纠正不要求用户分别维护Host和Stella两套画像；未来协作能使用更准确的当前解释。这些目标来自需求，不因采用官方组件而自动完成。
- **可证明的系统不变量：**声明入口首次供给前有真实资格；同一语义资产仅一份当前权威；发布对齐预期来源/版本，冲突不覆盖；当前状态与本次取代/失效记录一致发布；失败不冒充保存成功；下一请求不借旧资格。保护对象是声明读写入口，不是承诺对任意本机进程的文件保密。
- **语义效果目标：**原意判断准确、识别反证、澄清适当、后续不重复误解；需要真实模型和作者反馈，不能由JSON合规、hash、提示词或合成固定响应证明。系统能硬约束已登记资产的失效，但“已发现全部语义相关项”本身仍须评估，不得默认为真。

必要事务只覆盖一次语义资产发布所需的当前状态、修订/失效关系和来源绑定；多个必要记录不能半发布。Host索引与可重建投影可异步更新，但滞后/不可用不能被报告为完整同步，受控消费不能把旧投影冒充当前资产。不建立跨所有Host文件的大事务平台。Git是当前承载，原子/CAS保证保留，具体旧checkpoint实现可替换。运行中即时撤回、完美清洗历史、任意时刻完整认知快照不重回主线。
