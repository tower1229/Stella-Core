## 2. 两个验收范围

| 范围 | 必须证明 | 不据此宣称 |
| --- | --- | --- |
| Alpha | 按需关系／社交决策、真实行动证据、一个 Twin **或** Praxis 学习项、后续使用、远端同步和干净恢复 | 全量个人资料接入、多轮全库取证、写作共思、完整 Twin 更新、持续代办已经实现 |
| 完整记忆契约 | [Memory Lifecycle](contracts/MEMORY-LIFECYCLE.md)的接入、检索、交互学习和同步全部满足；两个代表场景可接续 | 另行缩减六类产品能力，或已经确定新的发布版本 |

完整产品的主动能力、持续代办和框架修订遵守既定授权。社交状态判断始终按主人求助触发。任何验收范围都不能引入词面语义路由、推断充当实际行动、强制行动回答或静默降级。

## 3. 完成条件分开表达

每轮结果分别记录：

- `responseKind`: `answer | clarification | collaboration | action_advice | outcome_ack`；这是响应语义，不增加持久 Agent，也不替代五种 CortexMode。
- `evidenceStatus`: `sufficient | material_unknown | conflicting`；操作故障通过明确错误返回，不能伪装成其中一种成功取证状态。
- `persistenceStatus`: `not_required | local_committed | remote_pending | synchronized | failed`。

`clarification` 必须说明会改变判断的关键未知，并提出可回答的问题；有充分证据的独立判断仍可表达。`collaboration` 必须推进具体思考并保存适用进展。只有证据和请求支持行动建议时，才要求具体下一步行动。不因满足格式而补造建议、事实或 Episode。

回复已生成、已投递、关键写入成功、远端同步成功是不同事实。关键写入失败时本轮不得报告全部完成；正常写入在 RPO 内可报告本地提交且远端待同步。确切投递状态由 Host receipt 决定，不能由生成文本推断。

## 4. 通用正确性门禁

| ID | 验证对象 | 必须观察到的结果 |
| --- | --- | --- |
| G-01 | 语义决策 | 路由、证据选择、关联与更新由结构化 LLM 判断；确定性部分只验证和执行 |
| G-02 | 响应类型 | 关键未知产生有效澄清，不触发强制建议；写作协作不产生虚构 outcome |
| G-03 | 证据性质 | 用户表达、他人转述、外部知识、模型推断可区分；后两者不能冒充实际行动 |
| G-04 | 预测 | 意义明确的选择预测在建议释放前封存；结果与纠正不改写预测 |
| G-05 | 生命周期 | 非法转换、重复结果、乱序回调、并发更新被拒绝或按同一操作幂等处理 |
| G-06 | 持久化 | 提交、pointer CAS、push、view 发布逐段故障可恢复；没有假成功或重复学习 |
| G-07 | 来源版本 | 更新 Twin 不使旧预测失真；删除来源后旧理解不可再被正常召回 |
| G-08 | 授权 | 已有委托可复用，范围外操作阻断；社交新资料不触发主动关系交流 |
| G-09 | 恢复 | 精确恢复所选 revision 的全部声明状态；合法空集合成功，缺失声明对象失败 |
| G-10 | 私有性 | 原文、个人事实、私有路径和模型输出不进入公开 fixtures、日志或 receipts |

Alpha 执行其路径涉及的 G 项及 Alpha 出口；完整记忆实现还须执行 Memory Lifecycle 的 M 项。未覆盖项必须逐项标注，不能用编译通过、一个顺利案例或 LLM 总分代替。

## 5. 语义诊断与真实使用

自动化验证可观察实现契约。语义评测用于定位推理和行为回归，必须记录用例版本、可用证据范围、模型及 rubric 版本。

评测按响应类型检查：`concreteNextAction` 在需要澄清时检查澄清是否适当，在协作时检查是否推进思考；旧字段名不允许强迫所有回答变成行动建议。无 outcome 时，不得伪造 retrospective endorsement。需要跳过的维度记录原因，不能由模型随意免除失败项。

真实效果由主人自然使用中的认可、拒绝、纠正和结果反馈决定；没有强制评分问卷或实际效果 A/B 分数门禁。一次认可不能推广为所有建议、论断或整个产品已通过。

## 6. 设计与源码的差异

2026-09-05 源码基线：`22a9b91187e9966b2d5c0fba7a624a3a47eb5a52`。本次是规范整理；以下是实现差异，不是保留旧行为的许可。

| 已确定的契约 | 该源码仍需收敛的部分 |
| --- | --- |
| 按响应语义完成 | 路由／评测尚未完整表达 responseKind；可写 Praxis 仍强制暂存预测 |
| 严格行动证据 | 新增 v2 Schema 排除 `inferred`；旧 runtime／路由、持久层和 fixtures 尚需统一迁移 |
| 历史与当前分别校验 | Episode 来源 pin 仍与当前文件比对；完整依赖失效和重算尚无实现 |
| 关键写入成功可观察 | finalize/end 回调仍承担写入；尚未证明 Host 失败时整个完成状态可靠 |
| 合法空状态恢复 | 当前 drill 要求重要开放 Episode 非空；须与专用覆盖 fixture 区分 |
| 完整记忆四段契约 | 尚无目录、操作日志、工作上下文、代际检索及同步协调的完整实现 |
| 完整配置契约 | 原有四个 Schema 及新增 Episode v2 Schema 不覆盖所有 portable registries 和 runtime profile |

本目录下新增格式是开发目标。实现新格式必须同时交付结构校验、语义不变量校验、显式迁移和对应测试；现有 v1 解码范围不能作为新行为的成功判据。更新线上私有数据或改变运行配置需通过实际任务的迁移／激活流程，本次整理不执行这些操作。
